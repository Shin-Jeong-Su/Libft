# Libft

42서울 0써클 첫 과제로, C 표준 라이브러리 함수들을 malloc/free 등 최소한의 시스템 함수만 사용해 직접 재구현한 커스텀 라이브러리입니다. 이후 진행한 거의 모든 C 프로젝트(Pipex, FDF, Push_swap, Minishell, Cub3d 등)에서 서브모듈로 재사용했습니다.

## 배경

C는 Python이나 Java와 달리 문자열 처리, 메모리 관리, 자료구조 조작을 위한 표준 유틸리티가 거의 없습니다. `strlen`, `strdup`, `split` 같은 기본 동작조차 직접 구현해야 하며, 이 과정에서 포인터 연산과 메모리 수명 주기를 몸으로 익히는 것이 이 과제의 목적입니다. 이후 프로젝트들의 기반이 되는 코드이기 때문에, 여기서 만든 버그는 뒤에서 진행한 모든 프로젝트에 그대로 전파된다는 부담이 있었습니다.

## 요구사항

- 외부 라이브러리 사용 금지, 표준 C 함수를 자체 구현
- `-Wall -Wextra -Werror` 옵션에서 경고 없이 컴파일
- 42 Norm(코딩 스타일 규칙) 준수 — 함수당 25줄 제한, 변수 선언 위치 등
- 정적 라이브러리(`libft.a`)로 빌드되어 다른 프로젝트에서 링크 가능해야 함
- 보너스: 연결 리스트(Linked List) 관련 함수 구현

## 기술스택

`C` · `Makefile` · `ar`(정적 라이브러리 빌드) · Pointer Arithmetic · Dynamic Memory Allocation

## 기능

- **문자열 처리**: `ft_strlen`, `ft_strdup`, `ft_strjoin`, `ft_split`, `ft_substr`, `ft_strtrim`, `ft_strmapi`, `ft_striteri` 등
- **메모리 조작**: `ft_memcpy`, `ft_memmove`, `ft_memset`, `ft_memchr`, `ft_memcmp`, `ft_bzero`, `ft_calloc`
- **타입 판별/변환**: `ft_isalpha`, `ft_isdigit`, `ft_isalnum`, `ft_atoi`, `ft_atol`, `ft_itoa`
- **출력 유틸리티**: `ft_putstr_fd`, `ft_putnbr_fd`, `ft_putendl_fd`, `ft_putaddr_fd`(포인터 주소 출력), `ft_puthex_fd`(16진수 출력)
- **연결 리스트(보너스)**: `ft_lstnew`, `ft_lstadd_front/back`, `ft_lstmap`, `ft_lstiter`, `ft_lstclear`, `ft_lstdelone` 등 단일 연결 리스트 생성·삽입·순회·삭제 전체 세트
- **파일 입출력**: `get_next_line` — 파일 디스크립터 기반 한 줄씩 읽기 기능도 포함해 다른 프로젝트에서 함께 사용

## 문제해결 및 예방

**`int`/`size_t` 타입 혼용으로 인한 루프 종료 조건 오류 (무한 루프)**
`ft_substr`, `ft_strtrim` 등에서 인덱스 변수를 `int`로 선언해두고, 부호 없는 `size_t` 타입인 길이 값(`len`)과 `(size_t)i < len` 형태로 캐스팅해 비교했습니다. 이렇게 부호 있는 타입과 부호 없는 타입을 섞어 비교하면 형변환 과정에서 종료 조건이 의도와 다르게 판정되어 루프가 끝나지 않는 문제가 발생했습니다(커밋 "INF loof ... solved"). 인덱스 변수 타입 자체를 `size_t`로 통일하고 불필요한 캐스팅을 제거해, 비교 양쪽의 타입을 일치시키는 방식으로 해결했습니다. 이후로는 크기·길이를 다루는 변수는 처음부터 `size_t`로 선언하는 것을 원칙으로 삼았습니다.

**`ft_calloc`의 정수 오버플로우**
`count * size` 값이 오버플로우되면 실제 필요한 크기보다 작은 메모리가 할당되어 이후 쓰기 작업에서 힙 손상이 발생할 수 있었습니다. 곱셈을 수행하기 전에 `size`가 0이 아닐 때 `count > SIZE_MAX / size`(코드상 `((size_t)-1) / size`) 조건으로 오버플로우 여부를 먼저 검증하고, 오버플로우가 감지되면 `NULL`을 반환하도록 방어 코드를 추가했습니다. (곱셈 결과를 만들기 전에 나눗셈으로 검사하므로 오버플로우 자체가 발생하지 않는 방식입니다.)

**`ft_lstmap` 실패 시 메모리 해제 로직 오류**
매핑 함수 실행 중 실패하면 이미 생성된 새 리스트를 정리해야 하는데, 초기 구현에서는 사용자가 지정한 `del` 콜백이 아니라 `free`를 직접 호출해 커스텀 구조체 내부의 포인터 필드가 새는 문제가 있었습니다. `free(f_result)`를 `del(f_result)`로 교체해 사용자가 정의한 해제 로직을 그대로 존중하도록 수정했습니다.

**`ft_putstr_fd`에 NULL 포인터 전달 시 크래시**
문자열이 `NULL`인 상태로 `write`에 전달되면 세그폴트가 발생했습니다. 이후 프로젝트에서 이 함수를 널 체크 없이 여기저기 호출하다 보니 반복적으로 같은 버그가 재현되었고, 근본적으로 라이브러리 함수 자체에 `NULL` 가드를 추가하는 것으로 해결했습니다. 이 경험 이후 "호출부에서 매번 체크"가 아니라 "라이브러리 레벨에서 방어"하는 방식이 재사용 코드에서는 더 안전하다는 걸 배웠습니다.
